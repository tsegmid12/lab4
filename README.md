## 1. Лабораторийн ажлын зорилго

Энэхүү лабораторийн ажлын хүрээнд Java хэл дээр бичигдсэн `GradeCalculator` классын функцуудыг JUnit 5 ашиглан нэгжийн түвшинд тестэлсэн.

Тестийн явцад дараах зүйлсийг шалгасан:

- Үнэлгээний оноог үсгэн дүн рүү зөв хөрвүүлж байгаа эсэх.
- Онооны хязгаарын утгууд зөв ажиллаж байгаа эсэх.
- Зөвшөөрөгдөх хэмжээнээс бага болон их утга оруулахад exception үүсгэж байгаа эсэх.
- Нийт оноог зөв тооцоолж байгаа эсэх.
- Parameterized Test ашиглан олон оролтын утгыг шалгах.

## 4. Тестэлсэн функцууд

### 4.1. letterGrade(double score)

Оруулсан оноог үсгэн дүн болгон хөрвүүлнэ.

| Оноо | Үсгэн дүн |
|---|---|
| 90–100 | A |
| 80–89.99 | B |
| 70–79.99 | C |
| 60–69.99 | D |
| 0–59.99 | F |

Мөн 0-ээс бага, 100-аас их болон зөвшөөрөгдөхгүй утгуудыг шалгаж, `IllegalArgumentException` үүсэж байгаа эсэхийг тестэлсэн.

### 4.2. totalScore(...)

Ирц, лаборатори, сорил болон улирлын шалгалтын оноонуудыг нэмж нийт оноог тооцно.

| Үнэлгээний хэсэг | Дээд оноо |
|---|---:|
| Ирц | 10 |
| Лаборатори | 40 |
| Сорил 1 | 10 |
| Сорил 2 | 10 |
| Улирлын шалгалт | 30 |
| **Нийт** | **100** |

Хэсэг тус бүрийн оноо зөвшөөрөгдөх хязгаараас хэтэрсэн эсвэл сөрөг утгатай үед exception үүсэхийг шалгасан.

## 5. JUnit 5 тестийн хэрэгжилт

`GradeCalculatorTest.java` файлд нийт **14 тест метод** бичсэн.

Тестүүдэд дараах боломжуудыг ашигласан:

- `@Test` — нэгжийн тест тодорхойлох.
- `@DisplayName` — тестийн тайлбар, нэр өгөх.
- `@ParameterizedTest` — олон оролтын утгаар нэг тестийг давтан ажиллуулах.
- `@CsvSource` — тестийн оролтын өгөгдөл тодорхойлох.
- `assertEquals()` — бодит болон хүлээгдэж буй үр дүнг харьцуулах.
- `assertThrows()` — exception үүсэж байгаа эсэхийг шалгах.

Тест бүрийг Arrange–Act–Assert (AAA) зарчмаар зохион байгуулсан.

### Шалгасан хязгаарын утгууд

- 100 — хамгийн их оноо.
- 90 — A үнэлгээний доод хязгаар.
- 89.99 — A үнэлгээний доод хязгаараас бага утга.
- 60 — D үнэлгээний доод хязгаар.
- 59.99 — F үнэлгээний муж.
- 0 — хамгийн бага зөвшөөрөгдөх оноо.

Мөн `letterGrade()` болон `totalScore()` функцүүдийн зөвшөөрөгдөхгүй оролтын утгуудыг `assertThrows()` ашиглан шалгасан.

### Parameterized Test

Хоёр `@ParameterizedTest` ашигласан:

1. `mapsScoresToExpectedGrade` — олон төрлийн оноонд тохирох үсгэн дүнг шалгана.
2. `addsAssessmentParts` — үнэлгээний хэсгүүдийн нийлбэр зөв тооцогдож байгаа эсэхийг шалгана.

## 7. Mutation Testing

Mutation Testing ашиглан тестүүд програмын логикийн өөрчлөлтийг илрүүлж чадаж байгаа эсэхийг шалгасан.

`GradeCalculator.java` файлын `letterGrade()` функц дэх:

```java
if (score >= 90.0)
```

гэсэн нөхцөлийг түр хугацаанд:

```java
if (score > 90.0)
```

болгон өөрчилж, тестүүдийг дахин ажиллуулсан.

### Mutation тестийн үр дүн

| Үзүүлэлт | Үр дүн |
|---|---:|
| Tests run | 26 |
| Failures | 2 |
| Errors | 0 |
| Skipped | 0 |
| Build status | BUILD FAILURE |

### Mutation өөрчлөлтийг илрүүлсэн тестүүд

1. `gradeBoundaryAtNinety` — 90 оноонд A үнэлгээ гарах ёстой боловч B гарсан.
2. `mapsScoresToExpectedGrade(double, String)[2]` — Parameterized Test-ийн 90 онооны оролтод A гарах ёстой боловч B гарсан.

Ингэснээр тестүүд `>=` болон `>` нөхцөлийн ялгааг илрүүлж чадсан.

Mutation тестийн дэлгэрэнгүй гаралт `results/mvn-test-mutant.txt` файлд хадгалагдсан.

### Mutation-ийг буцааж зассан үр дүн

Mutation шалгалтын дараа нөхцөлийг анхны зөв хэлбэрт буцаасан:

```java
if (score >= 90.0)
```

Дахин `mvn clean test` ажиллуулахад:

- Tests run: 26
- Failures: 0
- Errors: 0
- Skipped: 0
- BUILD SUCCESS

Ингэснээр эцсийн эх код зөв ажиллаж байгааг баталгаажуулсан.

## 9. Дүгнэлт

Энэхүү лабораторийн ажлаар JUnit 5 ашиглан Java програмын функцуудыг нэгжийн түвшинд хэрхэн тестлэх талаар дадлага хийлээ. Тест бичихдээ AAA зарчмыг ашиглаж, функцүүдийн хэвийн ажиллагаанаас гадна хязгаарын болон буруу оролтын утгуудыг шалгасан. Parameterized Test ашигласнаар олон төрлийн өгөгдлийг нэг тестийн аргаар шалгах боломжтойг ойлгосон. Мөн `assertThrows()` ашиглан буруу оролтын үед exception зөв үүсэж байгааг баталгаажуулсан. Mutation Testing хийхэд 90 онооны нөхцөлийг өөрчлөхөд хоёр тест алдаа илрүүлсэн нь хязгаарын утгын тестүүд ямар чухал болохыг харуулсан. Mutation өөрчлөлтийг буцаасны дараа бүх 26 тест амжилттай ажилласан. Энэ ажлаар зөвхөн програмын зөв үр дүнг шалгахаас гадна тестүүд програмын логикийн алдааг илрүүлэх чадвартай байх ёстойг ойлголоо.
